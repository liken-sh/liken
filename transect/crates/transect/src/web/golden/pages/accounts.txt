Ways in : every port that answers from outside the cluster, and the gates on the way to it.
Accounts : every account a binding names, and what it may do.
Not read
A workload's own TLS and sign-in are not in the API. A gate here is one the cluster's objects put in front of the workload, or one declared in stored text, which the people who run the cluster wrote.
Whether an address answers from the internet is not in the API.
Grants are read from Roles, ClusterRoles, and their bindings. A webhook authorizer, the node authorizer, and admission webhooks are not read.
The API server's version and feature gates are not read. Exec counts create on pods/exec and pods/attach , which a server from 1.35 on requires; an older one, or one with AuthorizePodWebsocketUpgradeCreatePermission off, also allows exec with get .
Some routes to another account are not followed: approving and signing a certificate request, creating a PersistentVolume, writing an admission webhook, and reading a Secret that contains a ServiceAccount's token, whose type a Secret's metadata does not show.
A Pod Security default in the API server's admission configuration is not in the API.
No Secret is read. A Secret is shown by its name, from the pod specs and Roles that name it.
